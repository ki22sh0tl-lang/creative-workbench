# AI 内容团队：模拟场景说明与验收

本次在原有框架中新增社媒内容工作流，保留原游戏广告项目的数据、字段和报表。

## 模拟范围

- 项目：AI 微缩生活实验室；账号：微缩生活研究所。均为虚构。
- 平台：小红书。模型支持抖音账号，但本次没有编造跨平台可比结论。
- 8 篇模拟作品：4 篇图文、4 条短视频；覆盖微缩美食、奇幻空间、制作过程、成品揭晓。
- 每篇都有灵感、选题、制作任务、审核通过的资产、发布计划、发布包、72 小时表现。
- 增加 1 条复盘和 1 个第二轮选题 / 待制作任务。
- 没有实际生成图片、视频，没有上传文件或向平台发布。资产只有元数据，文件与发布链接留空，模拟编号以 SIM-XHS 开头。

数据经过人为设定：制作过程的收藏率较高，成品揭晓的播放量较高，用于演示不同目标的取舍。这不是实验结果，也不证明某种叙事优于另一种。叙事方式与内容价值存在混杂；图文与短视频应分组查看。

## 跑通步骤

1. `npm run seed:social` 新增演示项目；重复运行检测已有项目，不覆盖修改。
2. `npm start`，访问 http://127.0.0.1:3000，切换到“AI 微缩生活实验室 · 模拟项目”。
3. 工作台查看待办，通过左侧各模块检查灵感 → 选题 → 任务 → 资产 → 发布包的关联。
4. 数据分析选择“小红书”和“图文”，观察作品数据与标签分组。
5. 对任一作品点击“创建下一轮任务”，填入单一测试变量和交付要求，然后保存。
6. 到“内容制作任务”找到新任务，确认来源选题、复盘来源发布包、继承标签均已保存。
7. 刷新页面，数据仍保留。真实案例准备好后，新建未勾选“模拟项目”的工作空间，避免把模拟与真实数据混在一起。

## 指标约定

- 每篇内容只录入一份发布后 72 小时累计值；采集日可晚于第 3 天，但数值必须仍为该固定窗口。
- 阅读 / 播放、赞、藏、评、分享、关注均为手工输入；未知值不能按零填写，需核实后再录入。
- 收藏率 = 总收藏 / 总阅读或播放。
- 互动率 = （总赞 + 总藏 + 总评 + 总分享）/ 总阅读或播放，不代表去重互动人数。
- 标签分组按平台、形式、标签 ID 拆分；多选标签的分组不可以相加。
- 已有表现数据的内容不允许修改内容 ID、发布日期或退回未发布状态。
- 本轮不含自动数据采集、报表修改、多时间窗、统计显著性或自动放量。

## 验证

`npm test` 覆盖旧广告链路与新社媒链路、数据隔离、历史快照、重复累计数拒绝、72 小时窗口、模拟来源校验，以及复盘到制作任务的关联。
